# Compact Permissions スキル

Claude Code のセッション中、`permissions.allow` などには許可した項目が次々追加され、
重複や冗長な項目が溜まっていく。このスキルはそれらを **意味を変えずに** 整理・圧縮する。

## 対象ファイル

以下のうち存在するものを対象にする(プロジェクト優先):

- `.claude/settings.json`
- `.claude/settings.local.json`

`~/.claude/settings.json`(ユーザー設定)は、ユーザーが明示的に指示したときだけ対象にする。

## 手順

1. 対象ファイルを Read し、`permissions` の `allow` / `deny` / `ask` 各リストを取得する。
2. 各リストに対して以下の圧縮を行う(**リストをまたいだ移動はしない**):
   - **完全重複の排除**: 文字列が一致する項目を1つに。
   - **包含関係の排除**: 既にある広いパターンに完全に含まれる狭い項目を削除する。
     例) `Bash(git:*)` があれば `Bash(git add:*)` は削除できる(前者が後者を包含)。
   - **ツール単位でグルーピングし、各グループ内をアルファベット順にソート**する。
3. 変更後の JSON を、元のインデント(2スペース)と構造を保って書き戻す。
4. 削除・統合した項目を差分として日本語で報告する(何件 → 何件、削られた項目の例)。

## 厳守すること(安全性)

- **権限を広げない**。狭い複数の項目を勝手に広いパターンに束ねてはいけない
  (例: `Bash(git add:*)` と `Bash(git commit:*)` を `Bash(git:*)` にまとめるのは禁止。
  これは元より多くを許可してしまうため)。削除してよいのは「既存のより広い項目に
  完全に包含される項目」だけ。
- `deny` リストは安全側なので、包含による削除はしても**内容を弱めない**こと。
- パターンの意味に確信が持てない項目は、触らずそのまま残す。
- 書き戻し後、JSON として妥当であることを確認する。

## パターンの読み方(参考)

- 形式は `Tool(specifier)`。例: `Bash(git status:*)`, `Read(~/.zshrc)`, `WebFetch(domain:github.com)`。
- `Bash(cmd:*)` は「`cmd` で始まるコマンド」に前方一致する。
  よって `Bash(git:*)` は `Bash(git add:*)` を包含する。
- specifier が完全一致、または一方が他方の前方一致プレフィックスのときのみ包含と判断する。
